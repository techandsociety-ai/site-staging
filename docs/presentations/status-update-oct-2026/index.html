Late July

Tests and CI

CI runs the full test suite before every deploy, with a failing test for each known bug and checks against published CHIP50 reports. Every run generates a report, published at techandsociety.ai/test-status.

August

Data cleanup

All 47 raw wave files went into one bucket, answers got their labels from the survey codebook, and a new loader rebuilt every wave in a sandbox. With Hong and Katya, we planned a sturdier data architecture to replace the old pipeline.

September

The AI profile and production polish

One codebase now runs three servers, including one for the Wave 38.6 AI survey, and chat.techandsociety.ai puts it in a browser. We tightened sign-in and access, logged every tool call and fixed a long list of bugs. Most important, we started building survey expertise into the MCP: it tells the model how to read each scale, says what every answer leaves out, and traces a report’s numbers back to the calls that made them.

Early October

Ready for early access

Wave 38 is complete, sentinel data refreshes itself, ChatGPT can connect, and a maintenance guide and alerts mean someone new can keep it running.

Every deploy is tested first

CI runs the suite before anything deploys, including checks against published CHIP50 reports, and generates a report of each run on the test-status page.

Every wave, from the raw files

All 47 raw wave files sit in one bucket, answers are labeled from the survey’s own codebook, and a new loader rebuilt all 722.7 million rows in a sandbox.

A sturdier data architecture

With Hong and Katya, we planned the pipeline that replaces the old one, built on Katya’s cleaned data and codebook. The new loader is its first piece.

One codebase, three servers

The same code runs the full panel, the Wave 38.6 AI survey and the sentinel data, each at its own address. CI checks the AI survey against 200 tables from Lazer’s own tabulation.

Ask from a browser

chat.techandsociety.ai, rebuilt on the project’s own cloud account, lets people on the roster ask the AI survey questions without setting up Claude.

Production polish

Each server has its own roster that admins edit without a redeploy, every tool call is logged with who made it, and a long list of bugs from Lazer and others is fixed.

Survey expertise, built in

The server tells the model how to read the data: which codes aren’t points on a scale, which wave asked a question, which cells are suppressed. Every answer names its source, and a QA tool traces a report’s numbers back to the calls that made them.

More data, more ways in

151 Wave 38 questions that were loaded but never served are now available, sentinel data refreshes itself every eight hours, and ChatGPT can connect as well as Claude.

Built to keep running

A maintenance guide with runbooks lets someone new run it, alerts email when a scheduled job fails, and retiring the old addresses cut Cloud Run costs.
