Reading the columns. Passing — the check holds in the code as deployed. Expected fail — a known problem that already has a test written for it. The test is marked xfail, so it reports as an expected failure and does not block a deploy; when the underlying issue is fixed, it flips to Passing. This is how a known gap stays visible instead of being forgotten. Failing — something broke that was not expected to. A failing check blocks deployment.

Do the tools reproduce numbers we already published?

Each row below replays a published report's own tool-call recipe against live data and compares the result to the figure printed in that report. This is the strongest check on the page: it fails when a number that is already in print stops reproducing.

46/46 checkable figures agree within tolerance across 8 reports — 25/25 independent · 21/21 consistency.

Two kinds of check, and the difference matters. An Independent row compares against a number the COVID States Project computed and published before this pipeline existed — a genuine external check. A Consistency row compares against a number this server itself produced earlier, which guards against the server drifting from its own prior output but proves nothing about external correctness. Consistency rows also target waves that are still open and growing, so small deltas there are expected drift, not defects — which is why their tolerances are wider.

What each of these 11 areas checks

Missing-value handling

Placeholder codes like 99 (“don’t know”) are left out of averages instead of being counted as real answers.

Derived-column denominators

Recoded and computed variables divide by the right respondents — rows the variable doesn’t apply to stay out of the base.

Non-answers kept out of averages

Codes like “Not sure” that sit at the top of a scale are shown in distributions but never averaged in as if they were the scale’s maximum.

Regression and weighting

Weighted averages and regression models compute the quantities they claim to, with survey weights applied correctly.

Known problems — a test is written and currently expected to fail; fixing the linked issue flips it to passing.
  • logistic uses GLM freq_weights, so SEs/p-values scale with Sigma(weights); survey weights are relative and inference must be scale-invariant — fix: #45 (2 checks)

Unordered categories

Questions whose answers have no order can be used to group results, but are never averaged or used as a numeric predictor.

Categorical crosstabs

The tool for unordered questions serves the right columns with the right labels.

The server says what it did

Every answer states the choices made on the reader’s behalf (weighting, exclusions, suppression), and the server refuses what it cannot do correctly instead of approximating.

Which survey weight

Each question gets the weight the survey team’s rule assigns (political or general, national or state), an explicit request overrides it, and every answer names the weight it used.

Grouped answers (recodes)

A grouping of a question’s answers gets a permanent id from its definition, survives a restart, and one user’s grouping can never change another’s.

Groupings in regressions

A regression on a grouped question keeps exactly the answers the grouping kept, as the crosstabs do.

Breakdowns into many groups

A breakdown into many small groups (counties, say) can be cut to the groups with enough respondents, and a ranking is not led by groups of one.
